## Overall Impression

The main app is a competently-built, domain-accurate dashboard held back mainly by accessibility and documentation gaps rather than visual failure. The PDF report is the real opportunity: it's functionally solid (popup-blocker-safe generation, correct data scoping, working pagination) but visually it's an app screenshot pretending to be an official university document — and that's exactly the surface meant to leave someone's hands and be read cold by a dean, auditor, or another institution.

## What's Working

1. **Popup-blocker-safe report generation** — `window.open()` called synchronously before any `await`, then redirected to a Blob URL. Most implementations get this wrong and end up randomly blocked in real browsers.
2. **Cross-referenced computed data** — "Vagas Ociosas" joins two independent datasets (enrollment + vagas projections) via a proper `ano+unidade` index, not a brute-force scan.
3. **Section 3 methodology disclosure in the report** — plainly explaining the evasão formula inside the document itself is exactly the transparency an auditor would want, and should be expanded rather than cut.

## Priority Issues

**[P0] Report typography reads as "exported dashboard," not an institutional document**
Why it matters: Inter is a neo-grotesque interface face with strong SaaS-product connotations (Notion, Linear, Vercel). Brazilian official documents (atas, ofícios, históricos) conventionally use serif body type to signal permanence. This is the single biggest thing standing between "PDF export" and "document a registrar would file" — confirmed by both the design review and the detector (5 separate Inter hits, 2 of them the report re-declaring its own font from scratch).
Fix: Pair **PT Serif** (headings + body + table prose) with **PT Sans** (uppercase eyebrows, column headers) — both built by Paratype specifically for official multilingual documents, same design family so they read as one coherent system. Alternative: Source Serif 4 + Source Sans 3. Keep numeric columns in a real tabular monospace (JetBrains Mono, already used in the main app) instead of Tailwind's unstyled `font-mono` fallback — the report's own `<head>` never imports it, so numbers currently fall back to whatever system mono the browser has.
Suggested command: `/impeccable typeset`

**[P0] Report has no masthead text or signature/protocol block**
Why it matters: institutional identity depends entirely on one hotlinked logo image with zero text fallback — if it fails to load (network hiccup, URL change, offline printing), the document proves nothing about who issued it. There's also no space for a responsible officer's signature, no protocol/document number, no "sem valor legal sem assinatura" language — nothing a document meant to be "stamped and filed" would normally carry.
Fix: Add a text masthead ("HISTÓRICO DE OFERTA DE CURSO — PROE/UEMS", full institution name spelled out) that renders independent of the logo image, plus a closing signature/protocol block.
Suggested command: `/impeccable typeset` then `/impeccable harden` (the harden pass covers the "logo fails to load" resilience gap)

**[P0] Silent batch-import overwrite risk (main app)**
Why it matters: `processBatchImport` treats `'novo'` and `'duplicata'` records identically and upserts both with no diff/preview/confirmation — despite the UI styling `duplicata` rows in red/danger. A visual danger signal that silently resolves to an overwrite, on an official enrollment database, is a real data-integrity risk for the exact power users (Alex) who run this "dozens of times."
Fix: Show a diff or explicit confirm step before overwriting duplicatas; or make the red tag informational-only with a required checkbox to include duplicates in the batch.
Suggested command: `/impeccable harden`

**[P1] Institutional navy applied inconsistently in the report**
Why it matters: `#003366` styles only the Section 2 table header; Sections 4 and 5 (the actual historical data, the report's substance) fall back to plain gray. There's even an unused `uems-blue-text` Tailwind utility defined but never applied anywhere. The brand color is a one-off accent, not a system — reads like a spreadsheet export with one styled header bolted on.
Fix: Extend the navy treatment (or a lighter tint of it) across all table headers and section rules consistently.
Suggested command: `/impeccable typeset`

**[P1] No accessibility support (main app)**
Why it matters: no Escape-key handling on any modal, icon-only buttons rely on `title` attributes only (no `aria-label`), no visible `:focus-visible` beyond input fields. For a public-university tool this is a compliance gap, not just polish.
Fix: Add Escape handlers, `aria-label`s on icon buttons, visible focus rings.
Suggested command: `/impeccable audit`

**[P2] Two washed-out neutral badges + one janky transition (detector-confirmed, quick fixes)**
Why it matters: `text-slate-600` on `bg-emerald-100` (situação/vagas-ociosas fallback badges) reads faint; `.progress-bar{transition:width}` can visibly stutter compared to a transform-based animation.
Fix: Darken the badge text (`text-emerald-800`+) or use `text-slate-700`; swap `transition:width` for `transform:scaleX` on the progress bar.
Suggested command: `/impeccable polish`

## Persona Red Flags

**Alex (PROE staff, generates reports repeatedly):** The batch-selection + "Relatório PDF (N)" counter and popup-safe generation genuinely serve this workflow well. But the P0 duplicata-overwrite ambiguity hits Alex hardest — exactly the person who eventually trusts the red warning tag, hesitates on a valid import, or worse, doesn't hesitate and silently overwrites something unintended. No "select all visible" or keyboard shortcuts despite this being repetitive work.

**Dean/Auditor (receiving the PDF cold):** No masthead text is the single biggest red flag — nothing proves institutional origin if the logo doesn't render. Inter + Tailwind pill badges read as "printed from a web app," undercutting credibility before the data is even read. No signature line or protocol number — an auditor doing compliance review expects accountability metadata that isn't there. Section 3's plain-language methodology is a genuine bright spot this persona would actually appreciate.
